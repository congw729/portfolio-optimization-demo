## 二、问题清单（按严重度分级）

### 🔴 阻塞级（0 项）

未发现会导致项目无法启动或文档根本性错误的问题。

### 🟠 重要级（3 项，建议本次修订即改）

**I-1. 5 角色设计与 jiuwenswarm 配置示例之间存在衔接缺口（位置：§1.4 ↔ §4.2）**
- 问题：§4.2 设计了 5 个 teammate 角色（data-collector / feature-engineer / optimizer-engine / viz-agent / reporter），但 §1.4 给出的 config.yaml 片段仅含 `agents: { leader: $agent_leader }`，未说明这 5 个角色如何在 jiuwenswarm team 模式中注册/创建。P4「拆 5 个 agent」阶段缺少前置配置依据；现场若新建演示团队，仅「增加新 team 段」的说明也不足以支撑 5 角色落地。
- 依据：文档 §1.4 配置片段与 §4.2 角色表、§6.2 P4 阶段描述。
- 修改建议：在 §1.4 或 §4.2 补充 teammate agent 的注册/创建方式——若通过 config.yaml `agents` 段扩展，给出 5 角色配置示例（含 member_name / persona / 职责）；若由 leader 运行时创建（任务看板 + 认领），明确说明该机制；并标注「⚠️ 需验证」后实测。需向作者确认：本团队实际如何注册 teammate 角色。

**I-2. 解析解与数值优化的约束假设不一致，演示易产生困惑（位置：§3.1）**
- 问题：§3.1 同时给出「解析解（推荐先用）」与「数值优化」，但解析解公式（GMV、切线组合）隐含**允许做空/无界权重**，而数值优化示例默认 `bounds=(0, 1)` 禁做空。两者在同一份输入下会得到**不同的权重与组合**（如解析 GMV 可能出现负权重），演示时若并列展示而未说明差异，观众会误以为结果矛盾。
- 依据：§3.1「解析解（推荐先用，直观）」+「bounds = [(0, 1)] * N 禁做空（可选）」；§6.3 坑 #4 虽提到负权重，但未点明「解析解与数值解在此处的本质差异」。
- 修改建议：在 §3.1 显式注明「解析解为无约束（允许做空）情形；禁做空需用数值优化」；演示脚本统一口径——要么全部用数值优化（禁做空），要么把「无约束 vs 禁做空」作为对比展示点（反而成为教学亮点），并在 A2 验收中注明权重校验按所选口径执行。

**I-3. Ledoit-Wolf 收缩兜底依赖 scikit-learn，但安装清单未包含（位置：§6.3 坑 #2 ↔ §1.2）**
- 问题：§6.3 坑 #2 的兜底方案「用 `sklearn.covariance.LedoitWolf` 收缩估计」，但 §1.2 的 `uv pip install` 安装命令未包含 scikit-learn。现场若协方差矩阵不正定，按文档兜底将因缺库而无法落地，且现场临时安装受网络限制。
- 依据：§6.3 坑 #2 明确引用 `sklearn.covariance.LedoitWolf`；§1.2 安装清单为 numpy/pandas/scipy/matplotlib/seaborn/yfinance/akshare/streamlit/jupyter。
- 修改建议：将 `scikit-learn` 加入 §1.2 安装命令（或注明「仅在需要收缩估计时按需安装，需提前固化版本」），并纳入 §1.5 requirements.txt 固化。

### 🟡 建议级（6 项，可在开发/彩排阶段处理）

**S-1. 「回撤曲线」多处出现但缺少计算定义（位置：§0、§4.2 viz-agent、§5.1 图表③、A6）**
- 问题：文档将「回撤曲线 / 最大回撤」作为必备输出与验收项（A6），但未给出回撤的计算定义与实现要点，实现者口径可能不一致（累计净值口径、是否含前高回看窗口）。
- 修改建议：补充一行定义：累计净值 `nav = (1 + r).cumprod()`；回撤序列 `dd = nav / nav.cummax() - 1`；最大回撤 `max_dd = dd.min()`；并注明「组合 vs 基准」用同一口径对比。

**S-2. 工期口径不一致（位置：§0 ↔ §6.2）**
- 问题：§0 总览写「约 1–2 周」，§6.2 写「约 8–12 个工作日」。1–2 周按 5 天工作周折算约 5–10 个工作日，与 8–12 工作日不完全对齐。
- 修改建议：统一为「约 2 周（8–12 个工作日）」或在 §0 直接引用 §6.2 的 8–12 工作日口径。

**S-3. 演示剧本时长紧贴 A7 上限，容错不足（位置：§5.3 ↔ §6.1 A7）**
- 问题：§5.3 剧本合计约 22 分钟，加可选交互 3 分钟恰为 25 分钟，正好压在 A7「总演示时长 ≤ 25 分钟」上限；现场任何环节延迟即超标。
- 修改建议：剧本预留 2–3 分钟缓冲（如交互压缩至 2 分钟，或标注「超时则跳过交互」），或将 A7 上限放宽至 30 分钟（需作者确认课程限制）。

**S-4. 有效前沿扫描未处理目标收益可行域边界（位置：§3.1 数值优化部分）**
- 问题：遍历 `mu_target` 从 `min(mu)` 到 `max(mu)`，在禁做空约束下，可行域两端（接近 min/max 单资产收益）可能无可行解，SLSQP 会报错或返回异常，导致前沿曲线两端截断/锯齿（与坑 #6 部分相关但角度不同）。
- 修改建议：扫描范围在 `[min(mu), max(mu)]` 内两端各留 5% 余量，并对每次 `minimize` 用 try/except 跳过失败点（配合 warm start），保证曲线连续。

**S-5. uv 安装的兜底缺失（位置：§1.6）**
- 问题：`curl -LsSf https://astral.sh/uv/install.sh | sh` 标注「⚠️ 需验证网络」，但未给安装失败时的替代路径。
- 修改建议：补一句：若脚本不可达，可 `pip install uv` 或退回 conda/venv 方案（§1.5 已有 venv 路径，两者衔接即可）。

**S-6. 数据截止日写死，演示日可能过期（位置：§2.1 代码示例）**
- 问题：`end="2026-08-13"` 为编写当日日期，若正式演示在更晚日期且需「新鲜数据」，需手工改参数；好在 §2.4 缓存方案使断网演示不依赖新数据，风险可控。
- 修改建议：注明「截止日建议按演示前最近交易日动态设置（如 `pd.Timestamp.today()`），缓存 CSV 用于断网兜底」，避免演示时因过期数据被提问。

## 三、亮点确认

1. **结构完整、三要素贯彻**：六大维度覆盖环境/数据/算法/集群/素材/验收全链条，每项均按「是什么 + 为什么需要 + 怎么获得/配置」组织，可直接作为执行手册，信息密度与可读性俱佳。
2. **风险标注诚实且有兜底**：全文约 9 处「⚠️ 需验证」均明确标注，绝大多数附兜底方案（本地 CSV 缓存、`assert 0 < rf < 0.15` 单位断言、备选数据源 akshare、预生成产物 + 录屏），风险意识专业。
3. **算法描述准确**：GMV 解析解 `Σ⁻¹·1/(1ᵀΣ⁻¹·1)`、切线组合 `Σ⁻¹(μ−rf·1)/(1ᵀΣ⁻¹(μ−rf·1))`、夏普比率、风险平价 RC 公式、Black-Litterman 逆优化 `π=δ·Σ·w_mkt` 均核验无误；`^IRX` 单位处理与断言正确。
4. **验收标准量化可测**：A1–A7 覆盖正确性（权重和 1e-6、GMV 波动率 ≤ 单资产）、真实性（非随机数）、协作可见性（≥4 agent）、现场稳健（断网 + ≤25min），与课程 demo 定位精准匹配。
5. **常见坑表覆盖面广**：9 条坑（网络限流/奇异矩阵/负权重/日期对齐/中文乱码/agent 数据不一致/现场 API 不稳等）均给出具体规避方案，尤其坑 #8（共享缓存 + lock）与坑 #9（确定性兜底 + 录屏）直击集群演示的核心风险。
